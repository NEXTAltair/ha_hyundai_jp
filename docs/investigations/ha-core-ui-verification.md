# 公式 HA Core コンテナでの画面・モニタリング検証

ユーザー指定の対象は HA の画面・設定・モニタリング。実車への遠隔操作は対象外。
ユーザーが Bluelink アカウントを設定した後、日本版 IONIQ 5 の1台・19エンティティが
利用可能になった。日本語表示、値と単位、10分間隔の定期取得、統合の再読み込み、
診断の画面からのダウンロードと伏字を確認した。

ブラウザでは初回の画面遷移で `Object`、一度のダイアログ終了で `disconnected` の
pageerror が記録された。後続の設定画面・入力検証・状態照会では再現せず、
対応する Core エラーもなかった。原因の特定はしていない。

## 入力検証の指摘

メール入力は `type=email` で、`invalid-address` に対して DOM の
`validity.typeMismatch` が true になる。それでも送信操作で、
メール・パスワードを含む config flow の継続 POST が発生することを二度確認した。
空欄の送信は止まる。

検証用ブラウザの request interception で、この POST は HA バックエンドへ到達する前に遮断した。
ダミーの資格情報を Bluelink に送信していない。
正しいメールアドレスでの設定に支障があるとは確認できていない。
今回アプリコードは変更せず、形式チェックを config flow 側でも行うかを後続の判断とする。

## 実データの表示と診断

デバイス画面で次を確認した。個別の車両名・識別子・座標は記録に含めない。

- 構成は sensor 7件、binary_sensor 11件、device_tracker 1件。操作用のドメインはない。
- 19件の日本語表示名を確認。「充電中」「プラグ挿入中」、ドアの「閉」などの状態も表示される。
- 駆動用バッテリーは初回97%、定期取得後97.5%。走行距離は画面で10,925.80 km、HA の生の state は10925.8。
  診断内の API 応答・解析結果・HA の state が一致し、走行距離の小数が失われていない。
  更新後の小数 SOC も、API 応答・解析結果・HA の state が一致した。
- 航続可能距離は km、充電の残り時間は min（画面では m）で表示される。
- 位置エンティティに有限の緯度・経度がある。「不在」は HA のホームゾーン外という状態であり、
  位置の取得失敗を表すものではない。実地点との照合はしていない。
- 「車両の最終同期」と「最終取得」が別のセンサーとして表示される。

診断の実応答では、設定の `email`、`password`、`unique_id`、解析済み状態の
`latitude` / `longitude`、元の応答の `GeoCoord` が `**REDACTED**` だった。
メールアドレス形式の文字列と既知の車両 ID が診断本文に残っていないことも確認した。
トークンや VIN はこの診断応答には含まれないため、実値を使った伏字の確認済みとは扱わない。

## 定期取得と再読み込み

ポーリング間隔を変更せず、ブラウザの状態通知を観察した。観察中に手動の更新は行っていない。
以下は JST。

| 観察点 | HA の最終取得 | 車両の最終同期 | SOC |
| --- | --- | --- | --- |
| 設定直後 | 16:06:54 | 16:04:01 | 97% |
| 最初の定期取得 | 16:16:54 | 16:11:02 | 97.5% |

HA の取得間隔は600秒。車両の同期時刻が HA の取得時刻と別に保持され、更新された値が反映された。
車両側の同期の契機・周期は、この1回の観察では確定しない。

その後、統合画面のエントリーのメニューから「再読込」を実行した。
16:16:57 に新たな取得が完了し、エントリーは `loaded`、1台・19エンティティがすべて利用可能だった。
前後でデバイス ID とエンティティ ID は変わらなかった。
実アカウントの表示・診断・定期取得・再読み込みのブラウザ検証では pageerror は記録されなかった。

今回確認したのは定期取得1回と再読み込み1回。長期運用、認証期限切れ後の再認証、
通信障害時の画面と復旧は、この実環境では検証していない。

## 検証環境の再開方法

検証用管理者の情報は、Git 管理外の
`local-private/ha-core-test/admin-credentials.json` に権限600で保存した。
操作補助スクリプト、空欄の設定画面のスクリーンショット、ブラウザの専用プロファイルも
同ディレクトリに置き、リポジトリには含めていない。
Bluelink の設定後は専用 Docker volume に Config Entry が保存される。

既存のログイン済みブラウザの接続からエントリー状態と登録エンティティを確認できる。
検証用スクリプトの出力は許可した項目だけに絞り、アカウント情報や座標、車両識別子を出していない。
ダウンロードした診断も同じ Git 管理外ディレクトリに権限600で保存する。

この端末の WSL 側 Docker ソケットは未構成だったため、Windows 側の Docker CLI を使用した。
Windows の PowerShell では `docker stop hyundai-bluelink-jp-ha-test` で停止し、
`docker start hyundai-bluelink-jp-ha-test` で再開できる。
